Remarks

The WCF service host has very specific requirements around the object type that you pass in when you call System.ServiceModel.Activation.ServiceHostFactory.CreateServiceHost(System.Type,System.Uri[]).

If you have a type that has a System.ServiceModel.ServiceContractAttribute on it and it implements an interface that has System.ServiceModel.ServiceContractAttribute on it, the WCF service host complains that you can't have two different service contracts.

The proxy generator uses a ServiceHostProxyBuilder to build the proxy types. This is specifically interesting in the CreateWcfProxy(Type, object) method, which uses some special overrides and additions in the builder.

The builder, when called through CreateWcfProxy(Type, object), generates proxy types that ignore non-inherited attributes on the service interface (e.g., System.ServiceModel.ServiceContractAttribute) so when the proxy type is generated, it doesn't bring over anything that will cause WCF host initialization to fail or get confused.
